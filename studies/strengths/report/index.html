What the engine does with exact facts from one large codebase

The CPython 3.13.7 standard library: 273,430 lines in 534 files, read with Python's own ast. No guessing: every fact is exactly true, and the truth for every question is computed in full, so a correct answer can never be scored wrong for being outside a partial key. 5,901 target facts were hidden from the engine. It got no rules; it had to learn them.

Summary

10.5 s · 210 MBbuild, learn and infer everything
  • Depth: it learned that inheritance is transitive and rebuilt the full ancestry of hidden classes, up to five generations, with proofs whose leaves are all stated facts.
  • Multi-premise rules: with CHAIN 3 it learned method → class → module → package and placed all 1,414 hidden methods in the right package. Without it, none.
  • Trees: with TREES 1 it learned Python's binding rules from the code alone: classmethod passes cls, staticmethod passes nothing, property and methods pass self, module functions nothing. Each rule held on every known case except the general "methods bind self" at 0.97, whose exceptions are the decorated methods.
  • Where it stops: the 72 hidden classmethod and staticmethod facts. The exact rule was learned, but more general rules outvote it; the engine answered 21 of them wrongly and labelled each tendency, and left the rest unanswered.

How to get there: state facts in the engine's language, then ask strictly

The same code, three pre-registered rounds. Round 1 stated the facts naively, and two targets were inexpressible in the rule language. Round 2 added two fact families read from the same ast nodes. Recall jumped, but tendency rules flooded the answers. Round 3 added the guide's setting for answers you act on, TENDENCYSTEPS 0.
