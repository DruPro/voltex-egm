What the engine found in real code and real data

31 datasets, 295 runs: four code corpora (254k to 400k source lines each), four real system tables, and synthetic shapes. 20% of every real dataset was hidden from the engine as an answer key. Below are the rules it learned on its own, step-by-step proofs of answers it recovered, where it goes wrong and why, and what the settings do.

Summary

  • Unicode: from character tables alone it learned that upper- and lowercase are inverses, that case partners share a script and text direction, and that accented letters inherit their base letter's properties. Checked against Python's Unicode database, 1,281 of 1,331 new facts are true (96.2%). 40 of the 50 errors are Unicode's documented exceptions; the other 10 come from how I extracted scripts.
  • Real Python code (125 packages): it learned call locality: a function that calls functions of module M is usually defined in M. It answers with 2-step proofs through chains of callers.
  • dpkg: one reversed rule labelled law, plus transitivity, grows the derived facts about 4× per round, 1.15 million in all. DEPTH 1 gives 13,000 facts at 88% true; the default DEPTH 4 gives 4% true.
  • TENDENCYSTEPS 0 is a per-dataset choice, not a fix. On Python packages, precision rises from 0.010 to 0.963 with the same recall. On company data, recall halves.
  • Infra: C1 (a cheaper joined check when building categories) gives identical output on 294 of 294 runs. It is up to 9.2× faster on large vocabularies and is now in the core.

1. Unicode: rules the tables imply, and the exceptions they hide

Input: 29,948 facts about 11,172 characters (U+0020 to U+2FFF): category, bidi class, script, case partners, decomposition. No rule was given. Learned rules, all but one at law tier:

x decomposes to y, y is in script s ⇒ x is in script s (tendency)0.94449

A recovered answer, with its proof

  • ⓝ Circled Latin Small Letter N has bidi class L law
    • ⓝ has uppercase Ⓝ law inverse of the stated fact
      • Ⓝ Circled Latin Capital Letter N has lowercase ⓝ (stated)
    • Ⓝ has bidi class L (stated)

The hidden key held this fact. The engine reached it in two steps: it turned a stated case pair around, then carried the partner's text direction across.

Measured against the key vs the real database

The key holds only the hidden 20% of the extracted range, so it marks true facts outside that range as misses. Checking every derived fact with unicodedata puts precision at 96.2%.

Characters it never saw

178 derived facts are about characters outside the extracted range, reached only through a stated case partner (for example Cherokee small letters, U+AB70 and up). 177 of them are true.

  • ꮆ Cherokee Small Letter Lo has bidi class L law
    • ꮆ has uppercase Ꮆ (inverse)
      • Ꮆ Cherokee Letter Lo has lowercase ꮆ (stated)
    • Ꮆ has bidi class L (stated)

Where it is wrong: Unicode's own exceptions

Of the 50 false facts, 40 land on characters that break the rule by design:

  • 30 Greek letters with iota subscript (ypogegrammeni/prosgegrammeni). Their capitals are titlecase (Lt), and their full uppercase is two characters. Unicode's simple case mapping agrees with the engine on the 25 uppercase facts; Python's full mapping, which I scored against, doesn't.
  • 6 one-way case pairs: the Kelvin, Ohm and Ångström signs, ß and ẞ, the theta symbol, and Cyrillic monograph uk. They lowercase to a letter whose uppercase is a different character.
  • 4 Balinese and combining vowel signs whose text direction differs from their base.
  • 10 script errors are mine: the extractor takes the script from the first word of a character's name, so "SMALL ROMAN NUMERAL" gets the script "SMALL".
  • ῼ Greek Capital Letter Omega With Prosgegrammeni has category Lu false: it is Lt (titlecase)
    • ῼ decomposes to Ω Greek Capital Letter Omega (stated)
    • Ω has category Lu (stated)
  • ᬻ Balinese Vowel Sign Ra Repa Tedung has bidi class NSM false: a spacing mark
    • ᬻ decomposes to ᬺ Balinese Vowel Sign Ra Repa (stated)
    • ᬺ has bidi class NSM (stated)

2. Real Python code: call locality, and a category error

Input: 64,763 facts extracted by the repo's own extractor (egm extract python) from 125 installed packages: definitions, calls resolved across modules, inheritance, imports, raises. Run with COVERAGE 0, because the default fails on code (see section 4).

Rule learnedTierAgreementCases known

a inherits from b, b is defined in m ⇒ a is defined in mtendency0.552,010
a is defined in m, m raises e ⇒ a raises elaw0.836
a is defined in m, m imports n ⇒ a imports ntendency0.9780 of 98,782

A recovered answer: two steps through the call graph

  • numpy _block_slicing is defined in numpy._core.shape_base tendency
    • _block_slicing calls _block_info_recursion (stated)
    • _block_info_recursion is defined in shape_base tendency
      • _block_info_recursion calls atleast_nd (stated)
      • atleast_nd is defined in shape_base (stated)

Both module facts were in the hidden key. The engine located two functions by following who calls whom, the way a developer reads unfamiliar code.

Where it is wrong: the last rule

"A function inherits its module's imports" agrees on 80 known cases, but applies to 98,782. It produces 100,859 of the 108,323 derived facts. That is a category error: imports belong to modules, not functions. It is accepted because agreement is measured only where an answer is known.

  • pip Bar.__repr__ imports rich.measure not a fact about functions
    • Bar.__repr__ is defined in rich.bar (stated)
    • rich.bar imports rich.measure (stated)

Recovered from the key: 1,783 of 108,323 derived facts. TENDENCYSTEPS 0 removes the bad rule but also call locality (73 facts left), so neither setting fits this data. Choosing between them is the user's call.

3. dpkg: depth decides between useful and a flood

Input: 14,296 facts about the 2,053 installed packages (depends, recommends, section, priority, architecture, source). Truth for depends on is the full transitive closure of Depends and Pre-Depends, so a correct indirect dependency counts as true.

New facts per inference round

Default DEPTH 4. Each round grows about 4×.

Share of derived dependencies that are true

Against the real closure: DEPTH 1 13,000 facts, DEPTH 2 60,537, DEPTH 4 1,151,048.

The cause: one reversed rule, labelled law

a recommends b ⇒ b depends on a agrees on 15% of known cases and still reaches the law tier. Combined with transitivity (27%), its errors chain:

  • fontconfig depends on fonts-opensymbol false
    • fonts-opensymbol recommends fontconfig (stated) reversed by the inverse rule

True indirect dependencies come from the same machinery:

  • libsystemd-shared depends on libcrypt1 true, in the closure
    • libsystemd-shared depends on debconf law
      • libsystemd-shared depends on libpam0g (stated)
      • libpam0g depends on debconf (stated)
    • debconf depends on libcrypt1 law
      • debconf depends on liblocale-gettext-perl (via debconf recommends debconf-i18n, which depends on it)
      • liblocale-gettext-perl depends on libcrypt1 law
        • liblocale-gettext-perl depends on perl-base (stated)
        • perl-base depends on libcrypt1 (stated)

All of the flood is law tier, so TENDENCYSTEPS 0 leaves it at 1,150,230 facts. DEPTH is the setting that matters here. With DEPTH 0 (until nothing new) the engine runs out of memory and crashes after 340 s, which is an infra bug to fix.

6. Infra: C1 in the core

Identical output on 294 of 294 comparable runs and 221 of 221 regression cells. One dpkg run with DEPTH 0 crashed at the memory cap on both versions. The clusters dataset (400 vocabularies that share no context) gained only 1.31×, below the pre-registered 1.5×.

Method and caveats

  • Pre-registered before the C1 runs (studies/stress/PREREGISTRATION.md). One deviation is logged: a bench bug that put a temp path in the compared output, fixed and rerun.
  • Sections 1-5 are exploratory. Their counts come from studies/stress/explore/*.json, written by tools/explore.py and tools/verify.py.
  • Keys undercount. The key holds only the hidden 20%, so a true fact outside it (an indirect dependency, a character outside the range) scores as a miss. Sections 1 and 3 re-score against full truth where it can be computed.
  • Extractors shape what can be learned. Two "discoveries" were artifacts of how facts were extracted. Check the extractor before trusting a rule.
